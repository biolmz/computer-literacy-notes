# Git 入门实验讲义

九份独立 PDF、八个能动手的小实验。从「文件夹怎么变成仓库」一路走到「删掉的提交怎么捞回来」。

每册 3~6 页，A4 打印优先，全文可搜索，字体已嵌入。**合计 45 页**。

---

## 这套讲义的特点

- **一册一个实验**。打印出来就是一张实验单，不用在几十页里翻找“我现在在第几步”。
- **六节固定结构**：命令速览 → 原理 → 动手做 → 做完必须对得上 → 卡住了先查这里 → 实验之后。八册版式一致，翻哪本都不会迷路。
- **每一步都写了「应该看到什么」**。输出对不上就说明走错了，当场能发现，不用带着错误往下做。
- **全程只动 `~/git-lab/`**。和你已有的项目完全隔离，八个实验做完整个删掉就行。
- **附一键还原脚本**。做坏了不必从头再来，重跑一次脚本就回到起始状态。

## 快速开始

**第一步**，打开 [00_开始之前.pdf](00_开始之前.pdf)，把 Git 装上、四项配置配好。这一步没做完，后面的实验会连续报错。

**第二步**，进到对应实验的文件夹，跑还原脚本：

```bash
# Windows（执行策略可能拦住 .ps1，所以带上 Bypass）
cd 实验文件/01_第一个仓库
powershell -ExecutionPolicy Bypass -File setup.ps1

# macOS / Linux
cd 实验文件/01_第一个仓库
bash setup.sh
```

**第三步**，打开同一个实验的 PDF，从「03 动手做」开始照着敲。

想从头再做一遍：

```bash
powershell -ExecutionPolicy Bypass -File setup.ps1 -Force    # Windows
bash setup.sh --force                                        # macOS / Linux
```

`-Force` / `--force` **不会删除任何东西**，它只是把旧目录改名成 `lab0N_bak_日期时间` 留在原地。确认不要了再自己删。

## 每个实验文件夹里有什么

| 文件 | 作用 |
|---|---|
| `setup.ps1` | Windows 一键建好 `~/git-lab/lab0N` 并写入起始文件 |
| `setup.sh` | macOS / Linux 的同一件事 |
| `files/` | 起始文件原件。不想跑脚本就手动复制一份 |
| `README.txt` | 该实验的目录名、需要哪几个文件、跑完应该看到什么 |

**建议用脚本，别手动复制。** 讲义里每一步都假设起始文件「一字不差」，而手动复制最常见的三个坑是：多了空行、换行符变成 CRLF、文件被存成 UTF-8 带 BOM。任何一个都会让 `git diff` 的输出和讲义对不上，然后你会花半小时怀疑是不是自己做错了。脚本写的是 UTF-8 无 BOM、LF 换行，和讲义里的输出完全一致。

## 环境要求

- **Git ≥ 2.23**。这个版本之后才有 `git switch` / `git restore` 两个专用命令，整套讲义用的是新命令。
- **Windows 用户用 Git Bash**（装 Git 时自带）敲讲义里的 git 命令，别用 cmd 或 PowerShell——两者对引号、路径、`Ctrl+C` 的处理都不一样，输出会对不上。还原脚本 `setup.ps1` 反过来，用 PowerShell 跑。
- **实验 01~06、08 完全离线**，只需要本机。
- **实验 07 需要**：一个 GitHub 账号、能联网、以及一次 SSH 密钥配置。
- 任意 PDF 阅读器。想打印就 A4 单面，正文没有跨页的大表格。

## 这套讲义不覆盖什么

`rebase` / `cherry-pick` / PR 评审流程 / `tag` 发版 / `bisect` 找 bug / Git LFS / 子模块——这些不在八册之内。不是它们不重要，而是没碰到真实场景时学了也记不住。先把「四个区域」和那几个救命命令吃透，剩下的查十分钟文档就能上手。

---

## 发现错误怎么办

讲义里的每一条命令、每一段输出都在本机跑过并核对过。但如果你照着敲却对不上，那大概率是我写错了，而不是你做错了——欢迎提 issue，注明是哪一册、第几步、你的完整输出。
